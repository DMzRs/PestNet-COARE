# Local validation of the preserved GitHub baseline

Validation completed on 7 October 2026. The tests used Python 3.12.14, PyTorch 2.4.1+cpu, and torchvision 0.19.1+cpu in an isolated local environment. COARE setup proposes Python 3.10 and a CUDA build; those still need testing on the allocated compute node.

In the initial package, every archived file was compared byte for byte with the ZIP, and all 254 files matched. The Git-ready revision omits only the two unused original weight pointers; all 252 retained archived files still match the original ZIP exactly. The executable runtime preserves each non-cache archived file exactly and supplies 78 missing framework files from the checksum-recorded official Ultralytics 8.3.18 wheel. Python 3.10 bytecode from the upload is retained in source but excluded from runtime so it cannot supersede the source. The custom model YAML, parser, attention code, and trainer are unchanged.

The baseline constructed successfully and completed a forward pass with input shape [1, 3, 640, 640]. It has 79,660,747 unfused parameters. The native fused inference model reported 79,638,859 parameters. These counts measure the supplied implementation and are not inferred from the paper. The fused count is 79.638859 M, which truncates to 79.63 M and rounds to 79.64 M.

A one-epoch CPU smoke test on two synthetic training images and two synthetic validation images completed loss computation, backpropagation, optimizer updates, validation, last/best checkpoint writing, and final checkpoint loading. The synthetic class mapping contained 102 entries to match the baseline. Its detection metrics are not an IP102 result or evidence of accuracy. Synthetic images and trained weights are excluded from the deliverable.

Resume was tested using the launcher's train and resume paths with an external test-only stop callback after the first saved epoch. Native save_period=1 retained the unstripped epoch0.pt snapshot. The resume path accepted its archived architecture and optimizer state, restored start_epoch=1, and completed epoch 2 of a configured 200-epoch run. The stop callback and synthetic dataset were used only by the local test harness, not by the delivered COARE launcher. Native last/best checkpoint stripping at finalization remains unchanged.

The dataset-YAML retargeting helper was tested with valid synthetic directory splits and a 102-class mapping. Shell syntax and Python syntax checks passed. Mock Slurm submission verified distinct CPU setup and GPU training options, explicit package working directory, output paths, and propagation of the package root. This does not validate access to a real Slurm account.

Full logs are in validation/check_cpu.log, validation/smoke_cpu.log, and validation/resume_cpu.log. They contain paths from the temporary local test workspace. No COARE login, Slurm submission, CUDA execution, GPU memory fit, author-result replication, or real IP102 training was performed here. Those checks remain for the allocated GPU test and dataset smoke jobs.

The package was subsequently updated at the user’s request to batch size 32 for full training and the real-data smoke job. The archive’s own README remains unchanged and still records batch size 16. The forward diagnostic now verifies fusion on a separate inference copy and reports both parameter counts; training source is not fused or edited. GPU memory fit at batch size 32 remains untested here.

The revised forward/fusion check passed, including numerical agreement between unfused and fused outputs. The smoke and train/resume paths were rerun successfully with batch=32 recorded in the native args.yaml. Those CPU tests still used only two synthetic training images, so their actual batches contained two images; they do not establish memory fit for 32 images on the COARE GPU. Updated logs are validation/check_cpu_batch32.log, validation/smoke_cpu_batch32.log, and validation/resume_cpu_batch32.log.

The Git-ready revision removes the source/runtime copies of ip102.pt and r200.pt, updates the expected file list, records their original checksums under omitted_archive_assets, and excludes future generated .pt files from Git. No Python model source, model YAML, trainer source, batch size, or training hyperparameter was changed for this repair.

Git round-trip validation passed using a local bare remote and an installed Git LFS pre-push hook: a normal push and fresh clone required no LFS objects. The test staged files with core.autocrlf=true to exercise Windows-style normalization; all 252 retained archived files still matched byte for byte after cloning, and the runtime checksum check passed. This tests the package and Git behavior, not authentication or branch protection on the user’s GitHub repository.
